# OZON 图搜并发保护策略

日期：2026-08-16
范围：浏览器上下文图搜请求的动态并发、保护性退避与运行状态输出。

## 策略

- 正常启动并发为 7 路。
- 稳定运行后每次提升 1 路，最高 9 路。
- 每累计 100 次成功且距上次提升至少 60 秒，允许提升一级。
- 遇到 HTTP 402、403 或 429 时，全局暂停新请求，并将并发降到 5 路。
- 连续保护错误按 15、30、60、120 秒退避，最长 120 秒。
- 冷却结束后，从 5 路按成功阈值逐步恢复到 6、7、8、9 路。
- HTTP 409 不触发全局降级；等待 1 秒后重试一次。
- HTTP 401 继续作为登录失效处理，不归入并发保护错误。

## 配置

- `OZON_HTTP_BASE_CONCURRENCY`：正常起步并发，默认 7。
- `OZON_HTTP_FALLBACK_CONCURRENCY`：保护回退并发，默认 5。
- `OZON_HTTP_MAX_CONCURRENCY`：并发上限，默认 9。
- 回退并发不得高于最大并发；正常起步并发不得高于最大并发。

## 状态输出

健康接口中的搜索池状态应报告：

- `configured`：当前实际放行并发。
- `base_concurrency`：正常起步并发。
- `fallback_concurrency`：保护回退并发。
- `max_concurrency`：并发上限。
- 冷却剩余时间、保护错误次数、最近一次保护错误和观测到的错误正文。

## 验收

- 无环境变量覆盖时，服务启动后 `configured=7`、`base_concurrency=7`、`fallback_concurrency=5`、`max_concurrency=9`。
- 并发提升不会超过 9。
- 模拟 402、403 或 429 后，当前并发立即变为 5，并进入对应冷却期。
- 冷却后成功请求可将并发逐级恢复。
- 409 只执行 1 秒等待与单次重试，不改变当前并发。
