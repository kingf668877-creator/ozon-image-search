# 页面生命周期自动清理设计

## 目标

刷新网页、关闭标签页或关闭浏览器时，删除该页面创建或恢复的任务，包括运行状态、等待处理、SQLite 记录、搜索结果和本地图片文件。

## 客户端契约

- 页面创建或恢复任务时，将任务 ID 写入 `localStorage.pendingCleanupTaskIds`。
- `pagehide` 和 `beforeunload` 触发时，使用 `navigator.sendBeacon` 向 `/api/cleanup_batch` 发送 JSON Blob。
- 生命周期事件中不立即清除本地任务 ID，避免请求未送达后无法补偿。
- 页面下次加载时先读取待清理 ID，通过普通 `fetch` 重新调用批量清理接口。
- 只有服务端明确返回成功后，才从 `localStorage` 删除已清理 ID。
- 手动删除、新建搜索时沿用同一清理函数，并等待服务端成功响应。

## 服务端契约

- `/api/cleanup_batch` 同时接受 `application/json` 和 Beacon 常用的 `text/plain` 请求体。
- 对每个任务先设置 `canceled` 和 `deleted`，使运行循环和待执行闭包停止继续写结果。
- 删除内存任务、SQLite 的任务/图片/结果记录及任务目录。
- 接口保持幂等：任务已不存在时仍返回成功。

## 生命周期行为

- 刷新页面：旧页面发送 Beacon，新页面加载后补偿确认删除。
- 关闭标签页：Beacon 尝试立即删除；下次打开页面时补偿。
- 关闭浏览器：Beacon 尝试立即删除；若浏览器终止过快，下次打开页面时补偿。
- 服务重启：不会自动恢复已标记待清理的页面任务；页面重新打开后完成补偿删除。

## 验证

- 创建测试任务后模拟 Beacon `text/plain` 请求，确认任务、图片和结果均删除。
- 模拟 Beacon 未送达，保留 `localStorage` ID，重新加载后确认补偿请求删除。
- 重复发送同一批任务 ID，确认接口幂等。
- 清理运行中任务后确认计数不再增长，搜索池最终无该任务产生的新结果。
