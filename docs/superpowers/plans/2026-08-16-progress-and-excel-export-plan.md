# 搜索进度与 Excel 导出实现计划

> 本计划只覆盖已确认的两项增量：下载/图搜双进度，以及将 JSON 导出替换为 Excel 表格导出。其他功能保持不变。

## 目标文件

- `index.html`
- `js/app.js`
- `server.js`
- `src/taskStore.js`
- `package.json`
- `package-lock.json`（安装依赖后由包管理器更新）
- 新增测试脚本或现有测试位置（按项目现有约定）

## 实施步骤

### 1. 保留并确认后端进度字段

文件：`server.js`、`src/taskStore.js`

- 保留现有 `downloaded_count` 和 `searched_count` 的累加、持久化与恢复逻辑。
- 检查 `/api/status/:taskId` 的字段始终是非负且不超过总数。
- 必要时为 URL 下载、直接上传、失败重试和服务重启恢复补齐一致的计数输出，但不改变计数语义和任务终态。
- 不改下载线程、图搜 worker、并发回退、状态机和结果排序。

### 2. 增加双进度界面

文件：`index.html`、`js/app.js`、相关样式文件（若现有样式集中在 `index.html` 则只改该文件）

- 在现有进度区域加入“下载图片”进度条和“图搜图片”进度条。
- 每个进度条显示：阶段名称、已完成数/总数、百分比。
- `applyProgress()` 使用 `downloaded_count` 更新下载条，使用 `searched_count` 更新图搜条。
- 保留现有总进度条、状态文案、预计剩余时间、并发与冷却提示。
- 对旧接口或字段缺失提供数值兜底，不让页面显示 `NaN`。
- 任务完成、部分完成、失败、取消、历史任务恢复时都正确刷新两条进度。

### 3. 增加服务端 Excel 导出接口

文件：`server.js`、`src/taskStore.js`、`package.json`

- 增加 `GET /api/export/:taskId.xlsx` 或等价清晰的导出路由。
- 从 SQLite 读取指定任务的全部图片行和结果行，不能只读取当前结果页。
- 对每张上传图片取结果数组中排序最前的一个商品作为最佳匹配。
- 通过稳定字段提取商品链接和商品主图链接；字段缺失时留空，不改变原始结果数据。
- 第一列嵌入任务图片的本地文件；本地文件不存在时写入原图名称或失败状态文本。
- 生成固定三列：`上传图片`、`商品链接`、`商品主图链接`。
- 设置首行表头、列宽、行高、图片缩放、浅色交替行和适合链接查看的单元格格式。
- 响应头设置正确的 Excel MIME 类型和带任务 ID 的 `.xlsx` 下载文件名。
- 无结果、失败和下载失败图片仍输出一行，商品字段留空。
- 导出异常返回现有风格的 JSON 错误，不影响任务运行。

### 4. 替换前端导出入口

文件：`index.html`、`js/app.js`

- 将按钮文本从“导出 JSON”改为“导出 Excel”。
- 将事件处理从 `exportJson` 改为调用导出接口并下载 `.xlsx`。
- 保留现有按钮位置和结果展示逻辑。
- 导出前校验当前任务 ID；没有任务时沿用现有提示方式。
- 处理服务端错误、下载失败和重复点击状态，避免生成空文件。

### 5. 依赖与兼容性

文件：`package.json`、`package-lock.json`

- 选择支持 Node.js 22、服务端写入单元格图片的 Excel 库；优先使用项目已有依赖，若不足再增加单一明确依赖。
- 安装后检查锁文件，确保生产启动可直接加载。
- 不在浏览器端引入大型 Excel 生成逻辑，避免大任务结果和图片占用前端内存。

### 6. 验证

- 静态检查：`server.js`、`src/taskStore.js`、`js/app.js` 语法检查。
- 接口检查：创建或使用隔离任务，确认状态接口同时返回下载和图搜计数。
- 双进度检查：模拟下载阶段、并行阶段、完成阶段、失败阶段和历史恢复，确认两条进度分别对应两个计数。
- Excel 检查：至少覆盖一张有结果图片、一张无结果图片、一张失败图片；确认每张图片都有一行，第一列有嵌入图片或名称，商品链接和主图链接取最佳匹配结果。
- 文件检查：验证下载文件扩展名为 `.xlsx`、MIME 正确、工作簿可被 Excel 或解析库打开，且没有 JSON 导出残留入口。
- 回归检查：确认上传、下载、图搜、任务取消、重试失败、分页结果和并发健康状态不发生变化。

## 交付顺序

1. 先完成依赖确认和服务端导出数据读取。
2. 再完成 Excel 生成接口并做独立文件验证。
3. 完成前端双进度与导出按钮接入。
4. 运行回归检查，重启生产服务并验证健康状态。
5. 提交并推送 GitHub。

## 明确不做

- 不改搜索请求和结果排序规则。
- 不改下载重试参数和下载并发。
- 不改图搜并发策略或保护回退策略。
- 不新增商品名称、价格、评分等导出列。
- 不移除现有结果分页和任务历史功能。
